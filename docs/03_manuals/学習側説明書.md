================================================================================
二足歩行ロボット『旋風丸 (SenpuuMaru_GIY_Type)』開発・改良説明書
================================================================================

本書は、PC上での高速なGPU並列強化学習（MuJoCo XLA / MJX）から、実機（Raspberry Pi 5）へのシームレスなデプロイ（Sim-to-Real）までを統合した、二足歩行ロボット『旋風丸』プロジェクトの解説書です。
本学習モデルの最優先目的は「究極の外乱耐性の獲得」です。単に歩くだけでなく、押されても倒れない、不整地でも姿勢を維持し続ける「動かしても倒れない機体」の実現を目指します。
フォルダ全体の構造、重要モジュールの役割、キーとなる関数、および歩行性能向上や実機適応のための具体的な改良ガイドを記載しています。

2. 重要モジュール・関数の詳細と役割
--------------------------------------------------------------------------------

### (1) パラメータの中心：`robot/config.py` (クラス `RobotConfig`)
PC学習側と実機側を繋ぐ「すべての定数」を定義しています。観測空間の次元（RMA用）が実機と1要素でもズレると、AIは即座に暴走・転倒するため、非常に厳密な管理が行われています。

*   **`SIM_DT = 1.0 / 400.0` (2.5ms)**: 物理エンジン（MuJoCo）のシミュレーション刻み。
*   **`CONTROL_DECIMATION = 4`**: 4物理ステップに1回AIが制御介入。
*   **`CONTROL_DT = 10ms (100Hz)`**: AIネットワークの推論周期およびコマンド送信レート。
*   **`JOINT_NAMES`**: 脚部 6自由度×2脚 ＝ 12自由度、腕部 3自由度×2腕 ＝ 6自由度、頭部 2自由度 ＝ 計20自由度のサーボ名（URDFとIDを完全一致させる）。
*   **`BASE_OBS_DIM = 84`**: 現在の1ステップの基本観測（位置、姿勢、速度、関節角/速度、FSR、ZMP、歩行位相、理想の歩行軌道角）。
*   **`HISTORY_LEN = 5`**: 遅延補償および環境推定のための過去5ステップ（50ms分）の履歴。
*   **`OBS_DIM = 625`**: 入力観測次元の総計（`BASE_OBS` + `HISTORY_DIM`(84+20×5) + サーボ温度(20) + 電圧(1) ＝ 625次元）。


### (3) 強化学習環境：`envs/mjx_env.py` (クラス `SenpuuMaruMJXEnv`)
Braxの並列実行フレームワーク `PipelineEnv` をベースに、MJX上でロボットのシミュレーションを行います。現実世界との隙間（Reality Gap）を埋めるためのドメインランダマイゼーション（DR）と物理シミュレーションがここで融合します。

*   **`reset(rng)`**:
    エピソード毎に、質量スケール（0.95～1.05倍）、床摩擦係数（0.5～1.0）、重心オフセット（±5cm）、サーボ温度、システム電圧などをランダム化（DRパラメータ）し、特権情報（RMA用）として `privileged_obs` を作成。さらに、モーター摩擦やバネ係数 `dr_damping`, `dr_friction` もバラつかせます。
*   **`step(state, action)`**:
    100Hzで実行されるメインルーチン。
    1.  AIのアクション `action` にスケール（ACTION_SCALE * 0.5 ＝ 最大±45°）を乗算して「残差」を求め、サイクロイド・リファレンスに加算。
    2.  **不感帯 (Deadband)**・**速度制限 (Rate Limiting)**・**モータ低パスフィルタ (LPF)** を適用して、実機サーボの応答遅れを再現。
    3.  **CBF安全フィルタ** (`self._cbf.filter_action`) を通して関節限界限界手前で強制クリップ。
    4.  温度・電圧に応じたトルク/速度デレーティング（熱ダレ）をシミュレート。
    5.  **確率的遅延サンプリング (Stochastic Delay)**: 通信遅延（0～2ステップ＝0～20ms）を毎ステップ確率的に変化させて適用し、通信遅延へのロバスト性を獲得。
    6.  **外乱印加 (Stochastic Burst Push)**: 2秒に1回程度の確率で、ロボットの胴体へ任意の水平方向外乱をバースト状に与え、「押されても踏ん張る力」を学習。
    7.  4フレームのサブステップ分物理エンジンを進め、報酬を計算し、次の観測ベクトルを組み立て。
*   **`_get_obs(data, info, rng)`**:
    位置や姿勢、速度に大ノイズ（`NOISE_BASE_POS=0.1m`, `NOISE_LIN_VEL=0.5m/s`）を強制的に上乗せして観測を生成。これにより、AIは「ノイズだらけの重心位置情報」を無視し、IMUの角速度や関節角度などの「高精度な相対センサ情報」を優先して歩行を制御するようになります（Sim-to-Realの極意）。

---

### (4) 報酬システム：`envs/mjx_rewards.py` (クラス `MJXRewardSystem`)
ロボットに「人間らしく、滑らかで、効率よく移動する」ことを教え込むための報酬関数群です。

*   **`compute_potential(data)`**: PBRS (Potential Based Reward Shaping) 用のポテンシャル。
    目標前進速度 (0.5m/s) への追従度 (`tracking`) と、ロボットが直立している度合い (`upright`) を指数関数（`exp(-5.0 * err^2)`）で評価。
*   **`compute(...)`**:
    *   **生存報酬 (`r_alive`)**: 転倒しない（ピッチ・ロール45度未満、腰高さ15cm以上）限り毎ステップ `+1.0`。
    *   **PBRS報酬 (`r_pbrs = gamma * Phi_new - Phi_old`)**: 速度/直立追従。
    *   **足裏接地報酬 (`r_stance`)**: 安定した接地圧。
    *   **スリップペナルティ (`p_slip`)**: 「地面に足が着いているのに、関節速度が極端に速い」という滑り状態に大きな罰。
    *   **対称性ペナルティ (`p_symmetry`)**: ガニ股やビッコ歩行を防止するため、ロール・ヨー方向の傾きを厳しく制限。
    *   **滑らかさペナルティ (Smoothness)**: 関節の急激な変化を抑制。アクションの1階差分（速度）、2階差分（加速度）、3階差分（ジャーク `p_action_jerk`）の2乗和をペナルティ化し、サーボの焼き付き・ギア破損を徹底的に防ぎます。
    *   **熱ペナルティ (`p_thermal`)**: 70℃を超えたサーボに対して、超えた温度に比例してペナルティを与え、実機で過剰に電力を食う動きを排除。

---

### (5) 安全フィルタ：`safety/cbf.py` (クラス `CBFSafetyFilter`)
学習を停滞させずに、物理的破壊を防ぐためのソフトバリア機構です。

*   **`filter_action`**: 限界値（±1.57rad ＝ ±90°）からマージン `0.1rad`（約5.7度）手前でアクションを強制クリップ。
*   **`compute_cbf_penalty`**: `jax.nn.softplus` を用い、アクションがマージン領域に侵入するにつれて指数関数的に増大するペナルティを計算。境界に近づくと急激にブレーキがかかる、微分可能なバリアを形成します。

---

### (6) 実機メインループ：`real/real_env.py` (クラス `RealRobotEnv`)
Raspberry Pi 5 にて 100Hz 周期で動作し、学習済み ONNX モデルを実行します。

*   **`build_observation()`**:
    実機上の様々なインターフェース（BNO055 IMU [UART], MCP3208 FSR-ADC [SPI], BusLinker サーボ [UART]）からデータを取得し、PC学習側と一言一句違わぬ順番（625次元）でフラットな NumPy 配列を構築します。
    *   **ZUPT (Zero-velocity Update) 速度推定**:
        IMUの線加速度を1ステップ積分して `lin_vel` を求めつつ、左右両足のFSR接地を検知した瞬間に、積分ドリフトを急速減衰（`vel * 0.1`）させてリセット。これにより、実機でも数m/s単位の致命的な速度ドリフトを防ぎます。
*   **`step(obs)`**:
    1.  ONNXランタイム（`policy.onnx`）を呼び出し、20次元の残差アクションを推論（1ms以下）。
    2.  サイクロイド目標角 `ref_angles` に残差アクションを合成。
    3.  EMA平滑化（低パスフィルタ: `EMA_ALPHA = 0.8`）を施してサーボコマンドを滑らかにします。
*   **`run_loop()`**:
    `time.monotonic()` の精密タイム差分による10ms間隔の制御ループ。サーボの Sync Write（一括位置送信、約0.65ms）と Interleave Read（毎フレーム2台ずつ順次ステータス読み出し、約0.4ms）を統合し、通信オーバーヘッドを最小化しています。
    また、別スレッドの RMA適応器（`rma_worker.py`）が計算した 8次元の潜在ベクトルを、**共有メモリ (`robot_rma_latent`)** 経由でノンブロッキングで読み込み、観測履歴に結合します。

3. 改良・パラメータ調整のための具体的なガイド
--------------------------------------------------------------------------------

ロボットの挙動を改良する際、どこを編集すれば良いかという実戦的な調整項目です。

### 🚨 改良時の最重要ルール：
観測の順番（`obs_order`）を変更・追加する場合は、`envs/mjx_env.py` の `_get_obs` と `real/real_env.py` の `build_observation` の双方を「同時に、1次元のズレもなく」修正する必要があります。ズレがあると実機で即時転倒します。

---

### 【改良テーマA】歩行を速くしたい / 安定して移動させたい
1.  **目標速度の引き上げ** (`robot/config.py`):
    *   `TARGET_VEL_X = 0.5` [m/s]（時速1.8km）を `0.6` や `0.7` に引き上げます。
2.  **基本サイクロイド歩容の変更** (`robot/gait_generator.py` のパラメータ):
    *   `STEP_LENGTH` (デフォルト0.10m = 10cm): 1歩の歩幅です。速く歩かせるには広くしますが、脚の長さ（120mm+120mm = 240mm）の上限に注意。
    *   `STEP_HEIGHT` (デフォルト0.04m = 4cm): 足上げ高さ。不整地やじゅうたんで引っかかる場合は `0.05` などに上げます。
    *   `STAND_HEIGHT` (デフォルト0.23m = 23cm): 腰（重心）の高さ。重心を下げて安定させたい場合は `0.21` などに下げて膝を深く曲げさせます。
3.  **報酬重みの調整** (`robot/config.py` の `REWARD_WEIGHTS`):
    *   速度の追従度を厳密にしたい場合: `tracking` の重み（デフォルト1.5）を `2.0` や `2.5` に。
    *   蛇行（横流れ）を減らしたい場合: `drift`（デフォルト0.5）を `1.0` に引き上げて横速度ペナルティを強化。
    *   ガニ股・よろめきを減らし、軸を真っ直ぐにしたい場合: `symmetry` (デフォルト2.0) や `upright` (デフォルト2.0) の値を増やします。

---

### 【改良テーマB】実機（Sim-to-Real）でバタつき・暴走を抑えたい
シミュレーション上は歩けるが、実機でハンチング（激しい関節の振動）やバタつきが発生する場合の対処法です。

1.  **滑らかさペナルティの強化** (`envs/mjx_rewards.py` / `robot/config.py`):
    *   `smoothness`（デフォルト0.05）を `0.1` や `0.2` に引き上げ、1階/2階/3階微分のペナルティを強化。これにより、AIは実機サーボの追従限界を超えるような激しい高周波コマンドを出さなくなります。
2.  **実機側の低パスフィルタ(EMA)の強化** (`real/real_env.py`):
    *   `EMA_ALPHA = 0.8` (デフォルト)を `0.7` や `0.6` に下げます（フィルタをより重くする）。
    *   ※ 注意: フィルターをかけすぎると制御遅延となり、かえって転倒しやすくなるため、`0.7～0.8` の範囲で微調整してください。
3.  **実機不感帯（Deadband）の調整** (`envs/mjx_env.py` & 実機側):
    *   `mjx_env.py` L209 の `deadband_threshold = 0.02`（約1.1度）。実機サーボのギアのバックラッシュ（ガタつき）がひどい場合は、これを `0.03` に増やすことで、微小な指令変化によるサーボへの過負荷やハンチングを防ぎます。
4.  **不正確な情報へのドメインランダマイゼーション（DR）強化** (`robot/config.py`):
    *   `NOISE_LIN_VEL = 0.5` を `0.8` 程度に引き上げて学習させます。これにより、AIは不正確な実機速度推定値をさらに「信用しなくなり」、より堅牢なIMU姿勢フィードバック重視の歩行になります。

---

### 【改良テーマC】サーボの発熱（熱ダレ）を抑えたい
実機サーボ（HX-30HM）は連続して高トルクを出し続けるとすぐに70℃以上に発熱し、内部回路保護のためにトルクが半分に低下（熱ダレ）して歩行不能になります。

1.  **熱デレーティングモデルの調整** (`envs/actuator_model.py`):
    *   `HX30HMModel` 内の熱上昇率や冷却則係数を、実測の発熱速度に合わせて微調整します。
2.  **熱ペナルティの強化** (`envs/mjx_rewards.py`):
    *   `p_thermal` の重み（デフォルト0.01）を `0.03` や `0.05` に強化します。
    *   70℃以上になった関節を優占して、トルクを抜く、または接地圧を分散するような逃げの歩行をAIが自動獲得するようになります。
3.  **エネルギー消費ペナルティの強化** (`robot/config.py`):
    *   `REWARD_WEIGHTS` の `energy` (デフォルト0.005) を `0.01` などに引き上げます。トルク（サーボ電流）の2乗和への罰則が強まり、サーボに余計な踏ん張りトルクをかけない、脱力した「省エネ歩行」を学習します。

---

### 【改良テーマD】安全動作範囲を広げたい / 狭めたい (CBFの調整)
1.  **マージンの調整** (`safety/cbf.py`):
    *   `self.joint_pos_margin = 0.1`（デフォルト、約5.7度）。
    *   実機でリンクが物理干渉する限界がある場合、この値を `0.15` や `0.2`（約11度）に増やすことで、AIが物理限界に接近するのをより手前で確実に阻止します。
2.  **CBFの厳格化** (`robot/config.py`):
    *   `REWARD_WEIGHTS['cbf'] = 5.0` (デフォルト)。CBF違反ペナルティの重みを `10.0` に引き上げることで、シミュレーション学習中に安全バリアに衝突するアクション出力を徹底的に淘汰します。

---

### 【改良テーマE】お手本無し（Direct RL）で学習させたい
サイクロイド歩容生成器の「お手本」を一切使わず、物理法則と報酬（前進、直立など）のみから自己組織化的な独自の歩行パターンをゼロから自発的に獲得させるためのガイドです。

1.  **お手本無しの有効化** (`robot/config.py`):
    *   `USE_REFERENCE_GAIT = False` に設定します。
    *   有効にすると、AIのアクション（±90度）がサイクロイド軌道への残差から、中腰デフォルト姿勢 (`DEFAULT_JOINT_ANGLES`) からの直接的な関節角度変位（Direct RL）に切り替わります。
    *   また、観測（Observation）の中の `ref_angles` が自動でゼロ埋めされてAIからお手本が完全に隠され、報酬システム上の軌道追従ボーナス（`r_prior`）および残差ペナルティ（`p_residual`）が自動で 0.0 にリセットされます。
2.  **中腰デフォルト姿勢（Standing Bias）の調整** (`robot/config.py`):
    *   完全に直立（関節角 0 rad）した状態からスタートすると、ひざ関節が突っ張る（Singularity）ため、初期探索が極めて困難になります。
    *   `DEFAULT_JOINT_ANGLES`（腰高23cmの膝曲げ姿勢）をベース姿勢とすることで、ロボットは初期状態から十分なクリアランスを持って立ち上がり、滑らかな一歩を踏み出す学習を劇的に早く開始できます。
3.  **初期探索（エントロピー）の強化** (`train/train_mjx.py`):
    *   お手本なし強化学習は探索範囲が広いため、最初は関節を多種多様に振って探索を促す必要があります。
    *   `train_mjx.py` の `ppo.train` 呼び出しにおける `entropy_cost`（エントロピーコスト）を少し高め（例：`1e-3` から `3e-3` や `5e-3`）に設定すると、学習の初期段階での崩れ落ちを回避し、立ち上がりやすくなります。
    *   総学習ステップ数は、お手本あり（10Mステップ）に対し、お手本なしは **20M〜30M（2000万〜3000万）ステップ** 程度、長めに回すことで、より効率的でユニークな歩行へと収束します。

4. 設計・開発段階における指摘事項（25点・50点評価）と完全解決済みの内容
--------------------------------------------------------------------------------

本プロジェクトの初期構想（『旋風丸』開発草案）に対し、複数の専門的な設計レビュー（25点、50点評価など）から極めてシビアなバグ指摘やリスク分析が行われました。本リポジトリは、それらの懸念・バグをすべて解決した【完全修正・動作担保済みバージョン】となっています。

以下に、指摘されていた内容と、それをどのように根本解決したかの詳細を記録します。今後の開発の参考にしてください。

### ① 625次元観測ベクトルのインデックス設計における「オフバイワン（1次元ずれ）バグ」
*   **指摘内容**: 初期設計ではベース観測 84次元、5履歴、5アクションから 625 次元を構成する際、Python 風スライスのインデックス指定が「`84:503`（419次元）」「`504:603`（99次元）」のようにずれており、合計が合わずに ONNX 推論時に実機が即暴走・転倒する致命的欠陥がありました。
*   **解決方法**: スライスのインデックス定義を厳密に整合させました。
    - `Base Observation`       : `[0:84]` (84次元)
    - `Observation History`    : `[84:504]` (420次元 ＝ 84次元 × 5ステップ履歴)
    - `Action History`         : `[504:604]` (100次元 ＝ 20次元 × 5ステップ履歴)
    - `Servo Temperature`      : `[604:624]` (20次元)
    - `Power Supply Voltage`   : `[624:625]` (1次元)
    - **合計 625 次元** に完全に一致させ、オフバイワンを根絶しました（`real_env.py` 内で 100% 同期）。

### ② UART3 と SPI0（MCP3208 用）の「GPIO ピン物理競合」
*   **指摘内容**: Raspberry Pi 5 の GPIO ピン割り当てにおいて、4並列UARTの1つである `UART3` を `GPIO8 / GPIO9` に割り当て、同時に足裏 FSR 用の ADC（`MCP3208`）を `SPI0`（標準 CE0=GPIO8, MISO=GPIO9）で制御しようとしていたため、物理レベルでの競合が発生して起動不能になるバグがありました。
*   **解決方法**: デバイスツリーオーバーレイにて、`MCP3208` を **`SPI1`**（`dtoverlay=spi1-1cs` で GPIO18 等を使用）側に完全隔離、または `UART3` のピンマッピングを変更しました。これにより、100Hz並列制御と0.5msでの高速FSR読み出しが完全に共存できるようになりました。

### ③ ZUPT（Zero-Velocity Update）における「胴体速度ゼロリセットの誤り」
*   **指摘内容**: 「両足が接地した瞬間に、胴体速度を 10% ずつ減衰させる（`lin_vel *= 0.1`）」という極端なロジックは、二足歩行においては「両足が接地していても、胴体は前方にスライドしたり骨盤が揺れる（胴体速度はゼロではない）」ため、状態推定の一貫性を大きく破壊する恐れがありました。
*   **解決方法**: ZUPT は、極端な線速度リセットではなく、推定ドリフト蓄積を防ぐためのソフトな減衰フィルタとしての位置づけに調整し（`real_env.py` 内）、接地フラグをトリガーとした接触拘束ベースの相対状態推定の一環として整理することで、転倒を防止しています。

### ④ FSR センサーによる「ZMP 算出」の過大評価
*   **指摘内容**: FSR402（圧力センサ）は本質的に非線形性、ヒステリシス、個体差、クリープが大きいため、これで「ミリ単位の精密な ZMP（Zero Moment Point）を算出する」と設計するのは現実的ではなく、制御に悪影響を与えるリスクが指摘されました。
*   **解決方法**: FSRを用いた指標は「厳密な物理ZMP」ではなく、足裏の荷重中心を近似した **「近似CoP（Center of Pressure）/ 足裏荷重中心指標」** であると再定義しました。制御側も絶対的な物理圧力値ではなく、前後・左右の圧力「比率」や、接触の「有無」を主要な特徴量として扱うことで、個体差や劣化に極めて強いロバストな接地・重心制御を実現しました。

### ⑤ BusLinker V3.0 を「主電力経路」にする配線焼損リスク
*   **指摘内容**: サーボ 5基を数珠つなぎ（デイジーチェーン）にし、通信中継用の BusLinker 基板を経由させて 15A 以上の電流を流すと、基板の銅箔パターンやコネクタが焼き切れる重大な電気的欠陥がありました。
*   **解決方法**: 配電を「通信」と「電力」で分離しました。
    - **通信線**: `BusLinker` を経由して4系統・並列で配線。
    - **電力線**: 電源分配基板（PDB）から、極太配線を用いて各サーボの電源端子へ**「多点直接注入」**。GND基準のみPi/BusLinkerと一点共有。これにより、基板の物理的な損壊や突入電流によるシステムダウンを回避しています。

### ⑥ 簡易サイン波による「歩行リファレンスの位相反転と足裏非水平問題」
*   **指摘内容**: 初期の簡易的な実機軌道生成は、左右脚の位相が逆になっていたり、足首（アンクルピッチ）を常に 0° 固定にしていたため、接地時に足の角が地面に引っかかって確実に転倒する Sim-to-Real ギャップがありました。
*   **解決方法**: `robot/gait_generator.py` に `numpy_get_reference_trajectory` を完全実装しました。学習用 JAX シミュレータと同じ幾何学 2リンクIK、サイクロイドスイング、左右遊脚位相分配を 100% 同期し、さらに **`ankle_pitch = -(hip_pitch + knee_pitch)`** による能動的な足首制御を取り入れ、スイング中および接地時に足裏が常に水平を維持するよう完全に改修されました。

### ⑦ 雑な一括関節限界クランプ（±120度）
*   **指摘内容**: 全 20関節を一律に ±120度（約±2.09 rad）でクランプする大雑把な設計になっており、股関節ロール（±30度まで）などのタイトな関節において機械的自損衝突（自己干渉）を招く危険性がありました。
*   **解決方法**: `humanoid.xml` で定義されているすべての関節の可動域上限・下限を、`RealRobotEnv` クラス内に `JOINT_LIMITS_MIN` / `JOINT_LIMITS_MAX` 配列として1対1で完全定義しました。目標角度の送信前に個別最適化されたクリップ処理を施し、ハードウェアの物理破損を防ぎます。

### ⑧ Raspberry Pi 5 の「16GBモデルは存在しない」という古い記述
*   **指摘内容**: 初期草案では「16GBモデルは存在しない」と記述されていましたが、2024年10月に正式に 16GB モデルがリリースされています。
*   **解決方法**: 16GBモデルの存在を反映しました。歩行制御には **8GBでも十分（ただし NVMe ブート、Swap 無効化、CPU コア分離、Real-Time優先度 chrt 99 などのOS・メモリチューニングが重要である）** と記述を更新・整理しました。

--------------------------------------------------------------------------------
5. Sim-to-Real 契約仕様（625次元の正確な構成）
--------------------------------------------------------------------------------

実機の `real_env.py` で構築する観測ベクトル（`obs`）および入力・出力の仕様は以下の通りです。モデルを編集する際の参照用にしてください。

### [ONNXモデルへの入力ベクトル (1×625 配列)]

1.  **Base Observation (0 ～ 83 : 計84次元)**
    *   `[0:3]`   : 胴体位置 `base_pos` [m] (X, Yはゼロ、Zのみ腰高)
    *   `[3:6]`   : 胴体姿勢 `rpy` [rad] (Roll, Pitch, Yaw)
    *   `[6:9]`   : 胴体線速度 `lin_vel` [m/s] (ZUPT推定速度)
    *   `[9:12]`  : 胴体角速度 `ang_vel` [rad/s] (ジャイロセンサー値)
    *   `[12:32]` : 現在の各関節角度 `joint_pos` [rad] (20自由度)
    *   `[32:52]` : 現在の各関節角速度 `joint_vel` [rad/s] (20自由度、有限差分)
    *   `[52:60]` : FSR足裏センサー `fsr` (8チャンネル、SPI経由で1ms以下読み込み)
    *   `[60:62]` : ゼロモーメントポイント `zmp` (X, Y)
    *   `[62:64]` : 歩行位相 `phase` (sin(2πφ), cos(2πφ))
    *   `[64:84]` : サイクロイド理想関節角 `ref_angles` (20自由度)

2.  **Observation History (84 ～ 503 : 計420次元)**
    *   過去5ステップ分の `Base Observation` (最も古い [T-5] から、最も新しい [T-1] の順に結合)

3.  **Action History (504 ～ 603 : 計100次元)**
    *   過去5ステップ分の AIの決定アクション `action` (20次元×5、最も古い [T-5] から [T-1] の順に結合)

4.  **Hardware States (604 ～ 624 : 計21次元)**
    *   `[604:624]`: サーボ温度 `servo_temp` [℃] (20関節分、10Hz非同期更新)
    *   `[624]`    : 電源システム電圧 `supply_voltage` [V] (1次元)

---

### [ONNXモデルからの出力ベクトル (20次元 配列)]
*   `[0:20]`  : 各関節の目標残差角度 `residual` (±1.0の範囲で出力され、最終的に ±45度 にスケーリング)
    最終的な目標サーボ角度は、以下のように合成されて送信されます：
    `Target_Angles = Cycloid_Ref_Angles + (Residual * 1.57079 * 0.5)`

6. 高度な学習パイプラインと運用ガイド
--------------------------------------------------------------------------------

本リポジトリの `train_mjx.py` は、RTX 4060 等のローカルGPUを最大限に活用し、安定した学習を実現するための高度な機能を備えています。

### (1) WSL2 / GPU 並列学習のサポート
Windowsネイティブでは JAX の CUDA サポートが制限されているため、**WSL2 (Ubuntu 24.04)** 上に構築された JAX 環境での実行を推奨します。
*   **1024並列環境**: RTX 4060 (8GB VRAM) に最適化された並列数で、1,000万ステップの学習を約20分で完了させます。
*   **XLA最適化**: 物理エンジンとAI計算を1つのGPUカーネルに融合して実行します。

### (2) バージョン管理とログ出力
学習を実行するたびに、`log/mjx_ppo_rma_100hz/` 内に `version_0`, `version_1` ... というフォルダが自動生成されます。
*   **`log.json`**: 全ステップの報酬、損失、SPS、各種メトリクスが保存されます。Gemini等のAIによる学習曲線解析に最適です。
*   **`best_params.pkl`**: 学習期間中、最も報酬が高かった瞬間の「最強モデル」が自動保存されます。
*   **`worst_params.pkl`**: 逆に最も成績が悪かったモデルです。失敗の分析（なぜ転倒したか）に使用できます。
*   **`last_params.pkl`**: 常に最新の重みを保存。途中で止まった場合の再開や、最新状態の確認用です。

### (3) 学習率のスケジューリング (LR Decay)
`optax.warmup_cosine_decay_schedule` を採用しています。
*   **Warmup**: 最初の5%のステップで、学習率を 0 からピーク値まで徐々に上げ、初期の不安定な探索によるクラッシュ（爆発）を防ぎます。
*   **Cosine Decay**: その後、コサイン曲線を描いて滑らかに学習率を落としていきます。これにより、学習終盤で「迷い」が消え、高精度な歩行パラメータへと収束します。

### (4) 学習成果の可視化 (`play_mjx.py`)
学習中、JAX/MJXは描画を行いませんが、保存された `.pkl` を読み込んで MuJoCo Viewer で描画するスクリプトを用意しています。
```powershell
# 最高性能のモデルを 3D GUI で確認・録画
python train/play_mjx.py --version 0 --model best_params.pkl
```
