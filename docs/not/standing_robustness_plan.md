# 外乱耐性直立制御 実装・検証計画

## 1. 最終目的

ロボワンの試合で胴体を突かれても、歩行せず、その場で両足を接地した直立二足姿勢を維持する。

優先順位は次の通りとする。

1. 外乱なしで直立不動を確立する
2. 小さい外乱から段階的に復帰能力を獲得する
3. 突きの方向・大きさ・タイミングをランダム化する
4. 未知条件と実機条件で合格性を確認する

歩行や前進速度は当面の対象外とする。`TARGET_VEL_X = 0.0` を維持する。

## 2. 現状の診断

`log/version_4/log.json` は、直立制御の成功を示していない。

- 生存ステップは最大でも約151、終盤は約88で、目標500に未達
- 報酬は全期間で負。`total_penalty` が約488から2200以上へ増加
- `training_progress` は最終的に1.9456となっており、総ステップ数の定義またはログ値が不整合
- `episode_curriculum_scale` は0時点でも1.9、途中で20を超えるため、外乱スケールそのものとして解釈できない
- KLは20,480 stepで18,305、後半も学習率が約1.5e-5まで低下しており、PPO更新が不安定
- したがって、version_4の報酬曲線では外乱耐性も直立不動も合格とは判定しない

## 3. 成功判定を先に固定する

学習中の平均報酬ではなく、同一seed群で次の評価を実行する。

### Gate A: 外乱なし直立

- 外乱: 0 N、プッシュ確率0
- エピソード: 500 steps = 5秒
- 初期状態: 同一の安定姿勢、速度0
- 合格: 20エピソード中18以上が500 steps完走
- 姿勢: roll/pitchの最大値45度未満、平均は10度未満
- 横移動: base XY変位の最大値を記録し、閾値を別途固定
- torque/safety barrier: 飽和に張り付かないこと

### Gate B: 軽い外乱

- 方向: 前後左右を均等化
- 力: 1、2、3 N
- 印加時間: 50 ms
- 印加間隔: 最低1秒
- 合格: 各強度20試行中18以上が転倒せず、外乱後1秒以内に姿勢誤差が基準へ戻る

### Gate C: 試合想定外乱

- 力: 5、7、10 Nを個別評価
- 印加時間: 50、100、150 ms
- 方向、タイミング、接触位置をランダム化
- 合格: 各条件で転倒率5%未満、復帰時間と最大姿勢誤差を記録

### Gate D: 未知条件・実機移行

- 学習seed、質量、摩擦、COM、遅延を評価時だけ変更
- 観測ノイズとアクチュエータ遅延を実測値に合わせる
- 実機では低い外乱から段階的に試験し、非常停止を常時有効にする

## 4. 実装フェーズ

### Phase 0: 計測と整合性修正

目的は、学習が何を評価しているかを明確にすること。

- `training_progress` を総環境ステップ / `num_timesteps` として一度だけ定義
- `training_progress` を1.0でクリップし、ログにも実ステップと進捗を分離して保存
- `curriculum_scale` は現在値と累積値を別メトリクス名で記録
- `episode_alive`、完走数、転倒数、最大roll/pitch、復帰時間を記録
- 報酬項目を「報酬」と「累積エピソード値」に分ける
- `reward_scaling`、`episode_length`、`num_envs`、`unroll_length`をログへ保存

完了条件: 同じ設定で再実行したとき、進捗が0から1を超えず、評価値の意味を一意に説明できる。

### Phase 1: 外乱なし直立の確立

- 外乱を完全に無効化
- `MAX_EPISODE_STEPS = 500`
- 初期姿勢、接地高さ、関節順序を固定して検証
- 初期の質量・摩擦・COMランダム化を無効化または最小化
- アクション範囲を小さくし、絶対関節目標を毎ステップ大きく変えない
- rewardは `upright`、角速度抑制、足裏接地、低いエネルギー消費を中心にする
- capture point、recovery、barrierの重みは、立位が崩れるほど強くならないよう上限を設ける
- PPOのKLを監視し、目標KLを超えた更新を抑制する

完了条件: Gate Aを満たす。満たさない限りPhase 2へ進まない。

### Phase 2: 軽い外乱への復帰

- 1 Nから開始し、Gate Bの各強度を順番に通す
- 外乱を確率だけでなく、力・方向・持続時間として明示する
- 外乱直後は倒れないこと、姿勢を戻すこと、足を過度に広げないことを報酬化
- 外乱なしエピソードを一定割合で残し、通常姿勢を忘れないようにする
- `r_recovery` と復帰ボーナスは、転倒回避だけでなく復帰時間で評価する

完了条件: 1、2、3 NのGate Bを順番に満たす。

### Phase 3: 試合想定の外乱耐性

- 5 N、7 N、10 Nへ段階的に増加
- 前後左右、斜め方向、異なる接触時間を混在
- COM、摩擦、質量、遅延のDRを徐々に広げる
- 学習用評価と別seedの検証用評価を分離
- best modelは報酬最大ではなく、Gate A〜Cの合格率最大で保存

完了条件: Gate Cを満たし、未知seedでも性能低下が許容範囲内。

### Phase 4: 実機移行

- シミュレーションで実機相当のPD、遅延、電圧低下、温度上昇を再現
- 低い力の手動試験から開始
- 転倒判定、トルク制限、通信断、非常停止を先に検証
- 実機データを再度DRへ反映

## 5. 各実験で必ず残す情報

- git commitまたは変更識別子
- seed、num_envs、num_timesteps、episode_length
- GPU、JAX/CUDA環境、実測SPS
- reward scaling、learning rate、KL、entropy、value loss
- 外乱の力、方向、持続時間、発生時刻
- 完走率、平均生存ステップ、最大roll/pitch、最大XY変位
- 外乱後の最大姿勢誤差、復帰時間、転倒率
- 使用したモデルファイルと評価結果

## 6. 次に実行する順序

1. Phase 0のログ整合性修正
2. 外乱なしの固定評価スクリプトを作成
3. Phase 1を短い試行で実行し、Gate Aを判定
4. Gate A未達なら報酬ではなく、初期姿勢・アクション適用・PD・接地・終了条件を検査
5. Gate A達成後にだけPhase 2の1 N外乱を有効化
6. 各Gateの合格結果をこの計画書へ追記

## 7. 他チャットへの引き継ぎメモ

最初に読むファイルは、この計画書、`robot/config.py`、`envs/mjx_env.py`、`envs/mjx_rewards.py`、`train/train_mjx.py`、最新ログである。

実装を始める前に、Phase 0のログ不整合を確認する。外乱耐性の報酬調整や10 N学習へ先に進めてはいけない。Gate Aの500 steps完走が最初の唯一の合格条件である。
